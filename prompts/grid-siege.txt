@Prism 现在就用 python 工具做单文件塔防游戏「Grid Siege」(内联 CSS+JS, 零外部依赖), 保存到 td/index.html。

【执行纪律 · 最重要】
1. 第一个动作必须是用 python 工具写文件 —— 不要先说"我的计划是…"然后停下。
2. 一轮内写出完整可玩文件(地图+循环+3 种敌人+3 种塔+经济+15 波+胜负+UI 全部到位), 不要"先写骨架下轮再补"。
3. 写完立刻继续用 python 工具自检 5 个纯函数、实玩逻辑, 发现 bug 就改、覆盖保存, 直到全部通过。自检也是调 python 工具, 不是用文字描述。
4. 每一轮都必须以 python 工具调用结束。只有当文件已保存、纯函数已验证无误, 才允许用文字报告"完成"。
5. 禁止把"我将…/接下来我会…"作为一轮的结尾。

【地图】网格 16 列 × 10 行。一条预定路径从左边入口绕到右边基地(你自己设计, 要有拐弯)。非路径格可建塔, 路径格不能建。

【核心循环】requestAnimationFrame 实时 tick。敌人沿路径逐格移动; 抵达基地扣 1 命。塔自动攻击射程内敌人。

【敌人 ≥3 种】normal(中速中血)/ fast(快低血)/ tank(慢高血)。每 5 波出一个 boss(血量 ×5)。血量与速度随波数递增。

【塔 ≥3 种】各有 cost/damage/range/fireRate:
  arrow 便宜/快攻/低伤/单体
  cannon 贵/慢攻/高伤/范围溅射(AoE)
  frost 中/中/中/附带减速 debuff
塔可升级 1 次(数值提升), 也可卖(返还部分金)。目标选择逻辑要一致(如"射程内血量最高的"或"最靠前的", 选一种贯彻)。

【经济】开局 100 金。击杀得金(normal 5 / fast 4 / tank 15 / boss 50)。建塔/升级扣金, 金不够禁止建。卖塔回收 50%。

【波次】共 15 波。每波按波数生成 normal/fast/tank 混合 + 间隔 spawn。一波清完 → 下一波(自动延迟 3s 或手动"下一波")。波次表用纯函数算(见可测性)。

【胜负】15 波全清 = 胜利; 命 = 0 = 失败。两种都能重开。

【控制】暂停/继续、1x/2x 加速、点空地+选塔类型=建塔、点已建塔=看信息/升级/卖。键盘空格暂停。

【持久化】最高通关波数存 localStorage, 刷新保留。

【UI】画布(游戏区)+ 侧栏(金币/命/当前波/最高波 + 塔类型选择栏 + 选中塔信息)。暗色主题, 窗口缩窄不溢出。

【可测性 —— 必须把逻辑写成纯函数并暴露, 无副作用】
  window.testWave = (n) => 第 n 波敌人类型序列(数组)
  window.testPath = () => 路径格子坐标数组(入口→基地顺序)
  window.testTargeting = (towerSpec, enemies) => 选中的目标(或 null)
  window.testCombat = (towerSpec, enemySpec) => {damage, debuffMs?}
  window.testEconomy = (gold, action) => 操作后金币
渲染逻辑单独, 不污染这些纯函数。

【完成后】用 python 工具逐个验 testPath/testWave/testTargeting/testCombat/testEconomy, 实玩 3-5 波逻辑(敌人沿路径/塔开火/溅射减速/金命波/boss 波)。发现错就改、覆盖保存。全部通过后, 再用文字报告完成并给绝对路径; 这时可以调一次 reflect 总结本次关键决策。
