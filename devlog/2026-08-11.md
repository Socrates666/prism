## 阶段 B · 自研引擎架构

| 文件 | 职责 | textual 对应 |
|------|------|--------------|
| `markup.py` | rich 风格 `[bold cyan]…[/]` → 样式段; 栈式嵌套; 256 色; 定宽换行 | rich.markup |
| `buffer.py` | 离屏 cell 网格 + box 绘制 + 按行 diff 刷新(每行末 SGR reset, 仿 pi); CJK 全宽 | (textual 无直接对应, 是渲染底座) |
| `css.py` | 极小子集 CSS: `#id{height;layout;border;padding;color}`, fix/auto/1fr | textual.css |
| `widget.py` | Widget 基类 + 纵向 flex 布局 | textual.widget + layout |
| `widgets.py` | Header / RichLog(滚动) / Static / Input(多行+光标) / Footer | textual.widgets |
| `terminal.py` | Win32 Console API(ReadConsoleInputW + VT) 主路径 + POSIX termios 后备 | textual.terminal |
| `app.py` | App: run/compose/on_mount/on_key/call_from_thread/query_one/theme | textual.app |

关键约束: **agent 后台线程 emit 必须经 `call_from_thread` 回主循环改 widget**(与 textual 同款线程模型)。

- `_win_translate` 验证: printable / enter / 方向键 / ctrl+c(ctrl+字母) / shift 全部正确。

## 阶段 F · pi 视觉块(外观真正对齐)

- 诊断: 阶段 B–E 只换了渲染引擎, emit 标记(`行动/观察/直觉`)和朴素文本流没变 → "看起来和之前一样"。
- RichLog 重构为 **entry/block 模型**:
  - `user()` 用户消息块(user_bg 背景)
  - `tool_start()→ref` / `tool_end(ref,…)` 工具块(pending/success/error 三态背景 + ✓/✗)
  - `thinking()` 思考块 / `cognitive()` 认知块(直觉/反思)
  - `write()` 普通行(向后兼容)
- 修复 `wrap_segments` 用字符数而非显示宽度的 bug → CJK 现在按全宽正确换行。
- buffer 新增 `fill_bg`(块背景填充); theme 加 user/tool/thinking/cognitive 的 256 色 bg token。
- shell.py emit 改用块 API(主 emit + 子 agent emit); 用户输入 `❯` 行 → `you` 块。
- 滚动改 unit 粒度(块始终完整, 不被裁断)。

## 复盘

- **为什么自研**: textual/rich 是重依赖; prism 实际只用了 RichLog+Input+Static 的子集,
  自研引擎 ~800 行覆盖全部用例, 外观更像 pi, 且 transcript 可读回(测试更强)。
- **风险**: Win32 原始终端是 ctypes 直调, 非 Windows 走 POSIX 后备(termios + ANSI 解析,
  尽力而为)。本机环境(Windows Terminal + Git Bash)为主路径。
