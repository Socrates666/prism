## 阶段 B · 阶段 0 破冰 + function-calling 转型（19:14–20:08）

### B1 · 第一版 Agent：文本 ReAct（310588e, 19:14）

先让东西跑起来再说。`prism/agent.py` + `model.py` + `shell.py` + `__init__.py`，271 行。

- **Agent**：ReAct 文本循环（`Thought:/Action:/Observation:` 正则解析）
- **显示自举**（原则 9）：agent 不直接 print，而是 emit 事件 dict，hooks 可替换
- **ModelBackend** 抽象 + OpenAIModel 实现，配置走环境变量（不绑死 provider）

配套：`.gitignore`、`pyproject.toml`（依赖 ipython/openai/textual）、`.env`（gitignore 掉）。

### B2 · .env 自动加载（3d94118, 19:22）

`__init__.py` 里加 `_load_env()`：读 prism 目录的 `.env` 填进 `os.environ`，**不覆盖已有**。
顺手加了 Windows 终端 UTF-8 强制（agent 输出含 `▸` 等 unicode，GBK 会炸）。

### B3 · @ 路由（dd5d9dd + abd6f86, 19:46–19:48）

实现"输入即授权"的第一步：在 IPython 里 `@alice 你好` → `alice.chat("你好")`。

走 `input_transformers_post`（IPython 在执行前对源码做变换）。规则全部**报错不静默**（零揣测）：
- `@name1 @name2` → 报错（不群发）
- `@`（裸）→ 报错
- `@name`（空消息）→ 报错
- name 不存在 → 报错
- 多行 cell 不碰 → 避免误吞 `@decorator`

**踩坑**（19:48 立刻修）：`_transform` 以为接收 `str`，实际 `input_transformers_post` 接收 **`list[str]`**（行列表）。这是 IPython 的真实接口，文档不显眼。改为 `def _transform(lines)`。

### B4 · 大转向：文本 ReAct → function calling（cfbaff2, 20:02）

运行后很快发现文本 ReAct（正则解析 `Action:`）脆弱、不可靠。决定**借鉴 prime-agent 的 `agent-loop.ts`**，重写为 function-calling loop。

**翻译记录**（写入 PLAN）：prime 的 `agent-loop.ts` → prism 的 `agent_loop.py`：
- function calling（非文本解析）
- 双层 while + `streamResponse(delta)`
- `executeToolCalls` 串行执行
- EventStream 事件流 + AbortSignal → prism 的 emit + abort
- **砍掉** compaction / steering / parallel（后续阶段再加）

新建独立模块 `agent_loop.py`（118 行）：`Tool` dataclass + `run_agent_loop()` + 事件协议（`agent_start`/`message_delta`/`message_end`/`tool_start`/`tool_end`/...）。Agent 变成它的薄壳。

### B5 · 修 BadRequestError（81252d4, 20:08）

function-calling 跑起来立刻撞 OpenAI 的格式要求：**喂回 LLM 的 `tool_calls` 每个必须带 `type: "function"`**，`content` 空必须传 `null`。

不依赖 model 实现是否带 type——**agent_loop 自己保证格式**（双保险，model.py 累积时也加 type）。这是从 prime-agent 翻译时遇到的第一个 provider 格式坑。

- **emit 跨线程桥接**：actor 线程 emit → `app.call_from_thread(log.write, ...)` 写 RichLog

### D4 · 流式分行修复（a93274a, 22:40）

## 阶段 E · TUI 焦点 bug 修复

用户报：「全屏功能有 bug，点击后输入框以外的部分失效。」

**复现**（textual Pilot headless 测试，最干净的红绿循环）：
```
初始 focused:            Input  id=dock       ✓
点击 transcript 后 focused: RichLog id=transcript  ✗ 焦点被抢
点击后打字 Input 值 = ''    ← 键盘输入完全丢失
输入框 :focus 样式: False    ← 边框失活
```

**根因**：`RichLog.can_focus` 在 textual 8.2.8 默认是 `True`。transcript 是只读显示区、不需要焦点，但默认可聚焦——鼠标一点它就把焦点从 Input 抢走，于是键盘输入全部丢失、`:focus` 边框样式消失。这就是用户说的「点击后失效」。

**修复**：`shell.py` 加 `Transcript(RichLog)` 子类，`can_focus = False`，compose 用它替代裸 `RichLog`。

**验证**（同一个 Pilot 循环，红→绿）：
```
点击 transcript 后 focused: Input id=dock     ✓ 焦点保住
打字后 Input 值 = 'abc'  has_focus = True      ✓
二次点击后 Input 值 = 'abc99'                  ✓ 多次点击稳定
```
且对真实 `PrismApp`（不是最小 stub）回归同样通过。

**教训**：textual 全屏套壳，所有「只读显示」widget（RichLog / 静态文本）都要显式 `can_focus = False`，否则点击抢焦点是 TUI 的经典坑。后续加更多面板（多 agent 分屏、状态面板）时，凡是只读的一律关焦点。

## 关键技术决策（为什么这么做）

| 决策 | 否掉的方案 | 理由 |
|------|-----------|------|
| function-calling（非文本 ReAct） | 正则解析 `Action:` | 文本解析脆弱；provider 原生支持可靠 |
| agent_loop 自己保证 tool_calls 格式 | 信任 model 返回 | provider 格式要求（type/content null）易变，集中兜底 |
| @ 路由报错不静默 | 容错/默认行为 | 原则 1 输入即授权，零揣测 |
| actor 递条子（inject） | `await b.chat()` 进入对方执行 | 避免跨线程 race；B 自己改自己状态 |
| 文件工具闭包绑 workspace | 靠 cwd | cwd 进程级，多 agent 会踩踏 |
| immutable base + ext/ 隔离 | reload 改核心 | 绕开 reload-vs-实例冲突 |
| textual 套壳（非裸 IPython） | 纯 REPL | 原则 5 无中断交互；多 agent 分屏需要 TUI |
