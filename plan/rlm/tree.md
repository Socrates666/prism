# ★ 认知树:一树两轴

> werden round 8–9 的核心结论。本篇回答:**树是什么结构、为什么一树两轴、搜索和自指到底差在哪。**

## 一句话

**认知树 = 主动推理搜索树,不是被动上下文仓库。一树两轴:causes(搜索/回溯)+ based_on(自指/套娃)。** 搜索 ≠ 自指——这是 9 轮 werden 最关键的一次撞墙。

## 一树两轴

```
session 根
 ├── 任务 α(树)
 │    [思维] "要解析这个仓库" ──causes──▶ [行动] spawn explorer ──causes──▶ [上下文] "42 个 py"
 │       │
 │       └ failed(撞瓶颈)── 回父节点 ──▶ [思维] "换个角度:先看依赖图"
 │                                                    │
 │      [反思] "我连用 3 种自顶向下都卡 ──based_on── (上面 3 个 failed 思维)
 │              是我分解问题的方式有问题"              │
 │              → 改分解方式本身                       ▼
 │                                            [反思的反思] "我反思时总倾向..."
 │
 └── 任务 β(树)
      [思维] "α 里的模式能复用" ◀──references── 任务 α 的 pattern 节点
```

**两条轴(用不同边):**
- **causes 轴(横向分治 / 搜索)**:A 引出 B 引出 C。撞瓶颈 → 标 failed → 沿父边回溯 → 另开一支。**这是搜索**(探索替代方案)。
- **based_on 轴(纵向自指 / 套娃)**:新思维 **基于** 已有思维(包括"我推理的方式")。反思能 based_on 一簇 failed 思维,抽象出 meta-pattern;反思本身还能被再反思。**这是自指**(推理过程成了对象)。

## 搜索 ≠ 自指(round 9 撞墙)

| | 搜索(causes 轴) | 自指递归(based_on 轴) |
|---|---|---|
| 做什么 | 用方法 A 解题 → 卡 → 标 failed → 试方法 B | "我连用 A/B/C 都卡在**同一种错** → 是**我分解问题的方式**有问题 → 改方式本身" |
| 对象 | 问题解 / 推理路径(替代方案) | **推理过程本身** |
| 推理过程 | **不变**(只换支) | **成了被改的对象** |
| 能套娃? | 否 | **是**(能反思"我反思的方式") |
| 是 RLM 自指? | ✗ | ✓ |

**round 8 把搜索树想清楚后,round 9 意识到"这不算自指递归"** —— 因为搜索只换支,不改推理过程。自指的关键是 agent 把自己的推理过程当对象来改。**reflect 工具(沿 based_on)才是自指递归的入口。**

> 这正是用户 round-2 早就说中的:"递归 = reflect 工具,可被再次反思。" round 8 的搜索树丢了这一层,round 9 找回来。

## 节点与边

### 两类节点(用不同边连)
| 节点类 | 含义 | 例子 |
|--------|------|------|
| **思维节点** | 决策 / 推理 / 反思 | thought / reflection / pattern |
| **上下文节点** | 事实 / 结果 | action / result |

> 思维节点之间用 **causes / based_on**;思维↔上下文用 **temporal / references**。搜索时按类型合理排开(思维链 vs 事实附件)。

### 节点状态(round 8 例子逼出)
| status | 含义 |
|--------|------|
| `active` | 当前 frontier |
| `failed` | 撞瓶颈,标失败,触发回溯 |
| `success` | 该支达成 |

### 边 relation
| relation | 语义 | 轴 |
|----------|------|----|
| `causes` | A 引出 B | 横向分治(搜索/回溯) |
| `based_on` | B 基于已有认知(含"我推理的方式") | 纵向自指(套娃) |
| `temporal` | 时间先后(默认边) | 线性回溯 |
| `references` | 跨树引用 | 森林内检索 |

## 失败回溯语义(round 8)

撞瓶颈 → 当前思维节点标 `failed` → 沿 `causes` 父边回父节点 → 从那儿另开一支重新想。这是**带回溯的树搜索**,搜索对象是 agent 自己的推理。

> **【open, round 8 α/β】** "标记失败、回溯"这个动作**谁干?**
> - (α) 主模型干:小模型拼 search-state,主模型读了决定标 failed/回溯/继续
> - (β) 小模型干:小模型是搜索器(评估分支、决定探索/回溯),主模型只在 frontier 生成
> 两种是根本不同的 agent。详见 [scribe.md](scribe.md)。

## reflect 工具 = 自指递归入口

reflect 是树里的一个 **action 节点**:agent 主动反思自己的某个 subtree → 产出 `reflection` 节点,沿 `based_on` 连回原节点。reflection 本身还能被再 reflect(套娃)。

```
[反思] "我的分解方式有问题" ──based_on──▶ (3 个 failed 思维)
       ▲
       └──based_on── [反思的反思] "我反思时总倾向..."
```

这是 RLM 自我指涉的物理实现:**agent 把自己的推理过程当对象,可改,可套娃。** core 不可变(reflect 是工具不是 core 特性),但 reflect 操作的树是可变 data → 真自指不破坏 core。

> **【open】** reflect 工具归 core 默认工具 还是 ext/ —— [route.md](route.md) 落地时定。

## 与现有机制的关系

| 现有 | 认知树落点 |
|------|------------|
| spawn(原则 13,横向分治) | R5:spawn = 子树(非 inject 字符串),子 agent 树是父树子树 |
| promote_node(涌现固化) | R6:高复用 pattern 子树抽成 ext/skills(L1→L2) |
| messages(工作记忆 L0) | L0→L1:认知事件自动挂树(零门槛) |

## 确定 vs open

- ✅ 认知树 = 主动推理搜索树(非被动仓库)
- ✅ 一树两轴:causes(搜索/回溯)+ based_on(自指/套娃)
- ✅ 搜索 ≠ 自指(关键区分)
- ✅ 两类节点(思维 + 上下文)用不同边
- ✅ 节点状态(active/failed/success)+ 失败回溯
- ✅ reflect 工具 = 自指入口(沿 based_on,可套娃)
- 🟡 谁控制搜索(α 主模型 / β 小模型)—— [scribe.md](scribe.md)
- 🟡 自指递归终止条件(收敛/深度/目标/资源,或"一直在场")
- 🟡 reflect 工具归 core 默认 还是 ext
- 🟡 森林膨胀剪枝阈值 —— [persistence.md](persistence.md)
