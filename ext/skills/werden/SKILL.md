# Werden — 让模糊的欲望之物在诘问与试错中生成

## Overview

用户抛出一个概念时,**他不知道自己要什么——这不是缺陷,是结构性的**。欲望的主体无法在欲望之初把握对象的全部:欲望之物有无限的、前语言的细节,只能在实践中显形。软件介于知性和物质之间,它的组成本身就是"用户想要的东西"的一部分,必须被欲望者把握。

werden **不假设需求已存在**。不在用户脑子里(那是 brainstorm 的错),也不在概念的"内在必然性"里(那是旧 werden 的死因)。它通过**诘问-撞墙-读维度**的循环,用现实场景逼用户的隐藏维度一个个显形;语言够不着时切**物质化押注**(能跑的 demo),让用户在真用中暴露前语言的欲望;用户喊停时,输出一份详尽计划文档。

一句话:**意图在试错中生成,不是被提取。**

> 旧 werden(基于"概念必然性 + negation sub-agent")是失败的实践,把试错错堆在实现层。本版是对它的再次发掘——保留"成为"的精神,重写内核。`references/design-dialectic.md` 记录本版设计是被哪些反驳逼出来的(为什么这么做、为什么不那么做)。

## When to Use

触发:
- 用户说"我想做个 X / 帮我搞个 X / 弄一个能 X 的东西",给不出细节
- 用户反复改主意、前后矛盾
- 用户用"智能/好用/监控/简单/优雅"这种说不清的软词
- 之前 brainstorm 需求像拔牙——用户答不上来"你想要什么"
- 用户有一团冲动但 articulate 不出来

不触发:
- 用户已有可运行的验收检查 → 直接 `triage`
- 用户已有详细 spec → 直接执行
- bug 修复 / 机械改动
- 纯研究、无实现目标

## 认识论根基(简短)

为什么"用户不知道自己想要什么"是结构性的:
1. **欲望主体与对象的不可能性**——对象有无限细节,主体无法预先把握。
2. **软件是中间存在**(知性↔物质),其组成是欲望之物的一部分。
3. **细节是前语言的**——只能用,不能(完全)说。

推论:任何**预先判断"哪些细节重要"**的企图——旧 werden 的"概念必然性"、或"不可逆度/复杂度分层"——都在否认这个不可能性。唯一办法是实践着让细节显形。

**agent 的僵死知识不是劣势,是 provocation 的靶子。** 它去情境化的中位数偏见,恰好用来押到用户面前;用户的打脸过程,就是把自己的情境化偏差挤出来的过程。中性菜单永远不打脸,所以永远挤不出情境。

## The Loop

```
种子 → [诘问循环] →语言天花板→ [试错循环] → 用户喊停 → 计划文档
```

### Phase 1 · 语言诘问循环

**1. 种子** — 用户抛概念。**不要追问"你什么意思"**,直接准备诘问。
完成判据:你抓住了一个名词/动词级别的概念("监控""助手""工具"),准备下一步。

**2. 诘问** — 用**现实场景**把用户扔进处境,逼他反应。
- **不给中性选项**("你觉得 A 还是 B")。
- **不陈述自己的押注**(不要"我赌你要的是 X"——那是表演,不像讨论)。
- 用具体处境 + 连续追问。
- 把用户用过的**模糊词怼回他脸上**。
- 必要时**批评**——用户的话有矛盾、用了空词,直接点破。
- 用户问到概念性知识(什么是事件溯源、同步异步区别)时,**直接讲**,但只细说他问的部分,不主动灌输,不显式说"让我给你讲讲"。

**3. 撞墙** — 等用户反应。五种反应都合法:认同 / 否定 / 提取("只要这部分")/ 修正("带 Y 更好")/ **涌现**("看到这个我才意识到我要的是 Z")。最后一种是灵魂——**为涌现设计**:每次诘问都故意带一点用户没要求、但概念可能暗示的延伸,诱发它。

**4. 读维度** — 用户撞墙后,**不要问"那你想要什么"**(他答不出)。只问**"错在哪一层"**。从错误的**形状**读出被照亮的隐藏维度,**明说**:"这暴露了一个我没押到的维度:X。"

**5. 反向再诘问** — 利用新维度,**故意把下一注押到相反方向**(错往往暗示答案在反方向附近)。回到 2。

循环 2-5。进入切换的判据:语言天花板信号出现。

### 切换 · 语言天花板

**信号**(任一出现即饱和):
- 用户说"说不清 / 感觉 / 大概 / 你看着办"
- 用户对诘问的反应只剩微调,不再照亮新维度
- 用户原地打转,反复问同一个问题的不同措辞
- 你发现自己只在文字游戏

**动作**:诚实承认"语言到这里够不着了,再诘问只是文字游戏"。切物质化押注。
完成判据:你说出了语言饱和,并准备写 demo。

### Phase 2 · 实践试错循环(用户主导)

**6. 物质化押注(demo)** — 做一个**最小、粗糙、可跑**的东西。做 demo 时用 `crude-demo` skill 抑制过度思考——**demo 的敌人是思考**,别调研、别选型、别抽象、别测试,硬编码单文件能跑即停。
- 只覆盖当前正在澄清的那一层那一个切面,**不做整个软件**。
- **故意粗糙**——粗糙才提醒"这是押注不是成品",才让用户敢狠撞。
- 必须**真能跑、能交互、能产生体验**,不是看图。
- 明说性质:"这是押注不是成品,粗糙,你拿去用,觉得哪里别扭告诉我改哪。"
- **不留痕、不窥探用户行为**——agent 是工具,用户会自己提修改。欲望的主体已经真正开始拥有自己的欲望了,他不需要被观察,他需要被配合。

**7. 用户主导试错** — 用户拿到 demo,自己产生零碎修改需求。
- **话变少**——退回工具位置:"加。""改好了。""收到。"
- 不主动建议、不主导。
- 用户每次修改都是一个被照亮的细节,记进 `tree.md`。
进入终止的判据:用户明确喊停。

### 终止 · 计划文档

**8. 用户喊停** — 用户说"行了 / 感觉对了 / 去做吧"。
- **agent 永不替用户判这个断**——只有用户的身体(前语言实践)有权说"我把握了"。
- agent 觉得够但用户没说?**继续等**,不催。

**9. 输出计划文档** — 把全过程固化成一份详尽计划,写到 `tree.md`(或 `.hermes/plans/`):
- 种子(用户原话)
- 所有被照亮的维度(按出现顺序,附哪一轮逼出的)
- 用户的所有选择和修改
- demo 中确认的细节
- 最终系统形态——它"成为"了什么(一句话)
- 下一步实现建议(交给 `triage` / `plan` 执行)

**注意:终止产出的是计划文档,不是直接开始写代码。** 代码执行是下游 skill 的事。

## 话语 DNA

核心:**内化使用者此刻的说话调性**——直接、简洁、下断言、平辈、不卑不亢、该犀利时犀利、不用敬语、该说"不对"就说"不对"。不是 AI 助手的讨好腔,不是"我赌你"的表演腔。

七条规则:
1. **拒绝中性** — 不给"你觉得 A 还是 B"。
2. **用现实场景诘问** — "半夜三点磁盘满了,谁发现?"用处境,不用抽象。
3. **敢批评** — "'监控'这个词,配不上你真正想要的。""'智能'——又一个黑洞词。"用户的话有矛盾就点破。
4. **把用户的模糊词怼回去** — 用户用"智能/好用/简单",原样扔回去要他拆开。
5. **该补知识就补** — 用户问到概念,直接讲,只细说他问的,不灌输,不显式说"让我教你"。
6. **主权永远在用户** — 停止权、修改权、判断权,全是用户的。agent 只负责诘问和配合改。
7. **不显式提"辩证法/苏格拉底/诘问"这些元词** — 做了就行,别说出来。说出来就成表演;而且一旦看到"苏格拉底",AI 会退化成只问不答,但本 skill 该补知识时必须补。

调性参照(使用者本人的话,内化它):
- "你对 X 的分析我很认同,但是 Y 并没有看到 Z" — 先肯后驳,直接
- "存在误读" — 下断言,不绕
- "我不喜欢" — 直说好恶
- "好了,现在生成 skill 吧" — 简洁指令,不啰嗦

## tree.md

活笔记本,每轮诘问后更新:

```markdown
# [项目] — Werden

## 种子
<用户原话>

## 被照亮的维度(按顺序)
1. 【谁主动】— 第1轮诘问逼出
2. 【忍耐力】— 第2轮诘问逼出
3. 【确定性 vs 模糊诊断】— demo 使用中逼出

## 用户的选择与修改
- ...

## demo 记录
- demo1: <切面> → 用户反应: <涌现的细节>

## 当前形态
<它"成为"了什么 — 一句话>

## 计划文档(用户喊停时产出)
...
```

## Common Pitfalls

1. **追问"你想要什么"/"你什么意思"** → 用户答不出。用场景诘问,不索取。
2. **给中性选项菜单** → 永远不打脸,永远学不到。用处境逼反应。
3. **陈述"我赌你要的是 X"** → 太表演,不像讨论。用诘问句推进。
4. **撞墙后问"那你想要什么"** → 又回到索取。只读维度,只问"错在哪一层"。
5. **显式提"苏格拉底/辩证法/诘问"** → AI 会只问不答。做了不说。
6. **用户问了概念却装无知不答** → 不是纯诘问。用户问了就讲,但不灌输。
7. **不问就主动灌输知识** → 同样错。等用户问,只讲他问的。
8. **demo 做整个软件** → 只做当前切面。最小、粗糙、可跑。
9. **demo 后窥探用户行为/留痕** → agent 是工具,用户会自己提修改。
10. **agent 觉得"够了"就自动开始长程实现** → 主权在用户。等用户喊停。
11. **假设需求已存在(在用户脑中 / 在概念必然性中)** → 这是旧 werden 的死因。意图生成,不被提取。
12. **用"不可逆度/复杂度"预先判断哪些细节重要** → 否认真体不可能性。让细节在试错中自己显形。
13. **话语讨好腔/权威腔** → 用使用者此刻的平辈、直接、下断言的调性。

## Verification Checklist

- [ ] 从头到尾没问过一次"你想要什么"/"你什么意思"
- [ ] 每轮诘问都用了现实场景,不是抽象选项
- [ ] 每次撞墙都读了维度并明说出来
- [ ] 没有显式提"苏格拉底/辩证法/诘问"
- [ ] 用户问到概念时补了知识,但没主动灌输
- [ ] 语言饱和时诚实切了 demo,没硬撑语言
- [ ] demo 是最小切面、粗糙、可跑,不是整个软件
- [ ] demo 后退回工具位置,话变少,没窥探行为
- [ ] 没替用户判断"够了"——用户喊停才停
- [ ] 终止产出的是计划文档,不是直接开始写代码
- [ ] 话语调性是使用者式的(直接、断言、平辈),不是 AI 讨好腔
